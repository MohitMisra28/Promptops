# PromptOps

A provider-agnostic platform that turns messy instructions (an event brief) into **validated structured JSON**
(schedule, announcement, task list, content pack), and makes prompt and model changes **measurable**.
Everything is free: Python + FastAPI, a deterministic mock backend, and an optional local model through Ollama. No API keys.

## Setup and run (exact commands)

```bash
python -m venv .venv && source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python scripts/seed_prompts.py                           # only needed if prompts/ is empty (it ships seeded)
python -m pytest -q                                      # 25 tests incl. the regression gate
python -m promptops.regression                           # 5 configs x 50 cases -> results/report.md + report.json
uvicorn app:app --reload                                 # experiment UI at http://localhost:8000
```

Optional real model (free, local): install [Ollama](https://ollama.com), `ollama pull llama3.2:3b`, then
`PROMPTOPS_ENABLE_OLLAMA=1 uvicorn app:app` (Windows PowerShell: `$env:PROMPTOPS_ENABLE_OLLAMA=1`). It appears in the model dropdowns and router.

Free deployment: `render.yaml` + `Dockerfile` deploy to Render's free web tier (or any Docker host / Hugging Face Docker Space).

## What is where

| Requirement | Where |
|---|---|
| One model interface, 2+ backends | `promptops/providers.py` (`Provider`, `MockProvider` x2 tiers, `OllamaProvider`), `config.py` |
| Streaming text + structured JSON | `Provider.stream`, `/api/stream` (SSE), `PromptOps.generate(stream=True)` |
| Versioned prompt registry | `promptops/registry.py`, `prompts/*.json` (variables, metadata, changelog, diff) |
| JSON-schema validation | `promptops/schemas.py`, `promptops/validate.py` |
| Repair, retry, timeout, fallback, errors | `validate.py` (repair), `pipeline.py` (retry with error feedback, timeout, fallback chain) |
| Caching, tokens, latency, cost | `cache.py`, `telemetry.py`, per-attempt accounting in `pipeline.py` |
| Routing by task, quality, speed, cost | `promptops/router.py` |
| Side-by-side experiment UI | `static/index.html` served at `/` |
| 50 fixed test cases | `data/test_cases.json` (generated by `scripts/make_cases.py`) |
| Regression runner + comparison | `promptops/regression.py` -> `results/report.md` |
| Failure log, architecture, AI usage | `docs/FAILURE_LOG.md`, `docs/ARCHITECTURE.md`, `AI_USAGE.md` |

## Results (from `results/report.md`, 50 cases)

| config | schema valid first try | valid final | instruction following | cost USD |
|---|---|---|---|---|
| v1 + small | 59% | 96% | 75% | 0.0029 |
| v1 + large | 94% | 98% | 77% | 0.0587 |
| v2 + small | 84% | 96% | 98% | 0.0039 |
| v2 + large | 94% | 98% | 100% | 0.0797 |
| v2 + router + fallback | 86% | 98% | 100% | 0.0276 |

Prompt v2 lifts the small model's instruction following from 75% to 98%, and the router matches the large model's quality at about a third of the cost.
Small is enough for announcement, task_list and content_pack but not for schedule (its timeout case needs the fallback).
"Valid final" is below 100% because two cases are *meant* to fail cleanly (all-model timeout, empty input) and one needs fallback when fallback is off.

## Honest limitations

- The two main backends are **mocks**: latency is simulated and prices are hypothetical, so absolute numbers are illustrative; the *mechanisms* (validation, retry, fallback, cost accounting, regression gating) are real and tested.
- The Ollama adapter was written against Ollama's documented HTTP API but not run in the build sandbox (no Ollama there). Try it locally and log anything odd.
- Cache is exact-match only; token counts for mocks are estimated (chars/4).
- Demo video: not included (cannot be recorded here). `docs/DEMO_SCRIPT.md` is a 6-minute shot list.
